- **Proposal:** P20261024-9170c4

- **Decision kind:** remove --disproved

## What the record reports

The record covers work directories `$MNT/.suite_fsx.<host>.<pid>` that are left on the mxfs mount after the row's EXIT trap ran `rm -rf`. The record's own wording: "what left them, and whether the rm -rf failed on mxfs or raced a writer, is not known". The sightings named are at **2/disk/caw/direct**: control b20261023-636cd6 and verification b20261023-989617. The record's next step asks for two things:

> "run the fsx_fail_files lap and the plain fsx row each with the trap's rm -rf logging its stderr and exit status, and the second writer stopped before the trap; establish whether rm -rf on mxfs failed (and with what errno) or the writer recreated a file inside the directory before its rmdir"

## Check 1: the mechanism in the code (read, holds)

- `tests/fsx_fail_files_node.sh:32` `MXFS_NODES=1 timeout -k 5 "$BOUND" "$FSXSH" "$MNT" > "$OUT" 2>&1 &`, `:33` `row=$!`. The writer polls the `timeout` process, and fsx.sh's EXIT trap runs inside its child. So the writer is still live while the trap runs.
- `:38` `while kill -0 "$row" 2>/dev/null; do`, `:39` `for f in "$MNT"/.suite_fsx."$(hostname)".*/fsxfile_*; do`, `:41` `sz=$(stat -c %s "$f" 2>/dev/null) || continue`, `:43` `dd if=/dev/urandom of="$f" bs="$sz" count=1 conv=notrunc status=none 2>/dev/null &&`. `dd` with `conv=notrunc` opens with O_CREAT and without O_EXCL. A file unlinked between the `stat` and the `dd` is therefore created again.
- `tests/suite/fsx.sh:22` `trap 'rm -rf "$W" 2>/dev/null' EXIT`. The rm's errors and exit status are discarded.
- `tests/suite/fsx.sh:77` `finish` is the last statement. `tests/suite/lib.sh:292` `suite_emit "$status" test "$measured" "$reason"` prints the RESULT line (`:108` `printf '%s\n' "$ln"`) before the script exits and the trap runs. So the mtime of the row's `.row.out` is a timestamp taken before the trap.

The race the proposal describes is possible as written. That shows a cause that could produce the leftover. It does not show which cause did.

What this measures: the one file left in the directory is an inode born 4 ms (one coarse-clock tick) after the row's last output. What it does not measure:

- whether the trap's `rmdir` ran after that create and failed legitimately with ENOTEMPTY,
- or whether it ran earlier and failed for some other reason.

Either order leaves the same final state: the directory mtime equals the file's birth, and the directory holds that one file. The rm's stderr and exit status were discarded (`fsx.sh:22`), and nothing traced the order. The proposal's sentence "the trap's final rmdir finds the directory not empty and the error is discarded" is therefore inferred, not observed. The record's next step asked for exactly this measurement (rm -rf stderr and exit status), and it was not taken.

## Verdict: REJECT

The proposal measured one instance, fxn3 at 2/net/mesh/direct. There it showed that the writer created a file inside `$W` while the trap ran. That is real evidence for the harness-race hypothesis. It is not yet direct evidence that the reported behaviour is not an MXFS defect, for two reasons:

1. **The rm -rf outcome was never observed.** The trap's stderr and exit status are discarded (`tests/suite/fsx.sh:22`), so no run shows rmdir failing with ENOTEMPTY after the writer's create. The timestamps cannot tell that order from "rmdir failed for another reason, then the writer's dd landed". The record's next step named this measurement, and it was not taken.
2. **The reported sightings at 2/disk/caw/direct were never examined.** They are b20261023-636cd6 lap fxc1 and b20261023-989617 lap fxv1. The proposal attributes them to the writer by analogy. The only test of the mechanism at that configuration (g2c_w14b, 3 laps) left nothing. The 09:09 series and the g2_w12b leftovers were not read either.

What would meet the bar:

- Run the lap with the trap logging what rm does: for example `rm -rfv "$W"` with stderr and exit status kept, or an `strace -f -e trace=unlinkat,rmdir,openat` of the trap and the writer. Show, for each leftover, an ENOTEMPTY rmdir that follows the writer's O_CREAT of the surviving name.
- Run the writer-stopped-before-the-trap arm on the same laps (for example, the writer stops when fsx's processes exit, before `finish`). It should show zero leftovers over a measured number of laps.
- Do both at 2/disk/caw/direct, where the record was reported, as well as at 2/net/mesh/direct.
