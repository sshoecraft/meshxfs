## Observations (they do not affect this verdict)

1. The lap proves the fix-in pull no longer copies files older than the row. It does not prove the fix-in pull still copies files the row itself writes. alloc_witness with `AW_ABORT_RANK=2` writes no /root/drc_* or fsx log, so a pull that selected nothing at all would also PASS this lap. For example, `run.sh:2270` requires `[ -e .mxfs_row_mark ]`, and a row path that never calls `mark_row_start` would pull nothing. That would be a new defect (evidence lost), not this one, so it does not stop this verification. The `remove --fixed` review should expect a measurement that a row which writes a capture after its mark still gets it pulled.
2. The record's `reproducer` field (`data/defects.json:4985`) still describes the old lap that planted the capture only (`plants /root/drc_blkdump_planted_<label>/dmesg_at_fail.txt dated 2026-07-26 on each node`). The lap that ran plants the fsx log too (`tests/row_pull_since_start_lap.sh:11-13`). The field needs updating when the record is next written.
