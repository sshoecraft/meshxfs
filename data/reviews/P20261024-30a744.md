## Notes, not grounds for this verdict

- The lap triggers the defect with a runtime write (watch_ino), not a module reload with other arguments. The original observation was the reload case (dead_timeout_ms after a rejoin). The fixed comparison reads the live `/sys/module/mxfs/parameters` values either way (`run.sh:354`, `:364`), and `dead_timeout_ms` is not in the counter filter. The reload path itself was not run on the fixed code.
- The argument says the fix compares "every owner-writable parameter, not a list". In fact, the counters at `run.sh:315-331` are excluded. The proposal's own `cause` text says so ("counters filtered out"). A row that leaves a filtered counter changed would still not be refused.
- The fix refuses the pair (`row2.log:33` `ERROR: cluster is prepped for ...`); it does not re-prep it. The record's `next` allowed either.
- The supporting 4096-byte-LUN pair (`b20261024-8c3ba5` / `b20261024-f04950`) is consistent with this pair. The removal does not rest on it.
