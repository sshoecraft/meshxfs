- **Configuration is nominal.** The laps hold no VMs (each lap log :2 `=== VMs held for the lap: none ===`). The defect is in host tooling that takes no configuration (tools/batch_lap.py:247), so 2/net/mesh/direct is nominal, as data/reviews/P20261023-fa992e.md:66 also notes.
- **Clean exit leaves leftovers alive.** run_bounded kills the lap's processes only on an overrun. A harness that exits within its bound and leaves a background writer behind still leaves it running (:269-270 `return proc.wait(timeout=bound)`). That is outside this record, which names the expiry case, and it is not measured here. If it is ever observed, it is a new record.
- **Remote processes are out of reach.** Processes a harness leaves running on the test VMs over ssh are not local descendants, and run_bounded cannot reach them. The record's observed late writes were local files (P20261023-52a18d.md:24-26), so this does not bear on the record. It is not measured here.
- **CHANGELOG.md:14 now matches the fix.** It reads `**A batch lap that overruns its bound ends the processes it started, its harness's writers included**`, which no longer claims "everything", and names the three shapes measured.
