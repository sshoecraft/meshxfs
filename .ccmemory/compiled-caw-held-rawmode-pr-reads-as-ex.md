MXFS coherency and recovery traps with one failure shape: a cheap proxy for the real state (a code-reading inference, a lock-mode accessor, `i_dlm_mode`, a change count, a hash such as srcversion, dynamic membership, a per-case marker, a clean audit, a task label) was treated as the fact it only correlates with, and verification that exercised one lap, one call site or one mechanism passed. Each was caught by measuring the real thing. Part 1 is lock-mode proxies, part 2 change-count, build-identity and task-label proxies, part 3 the sole-survivor, takeover and crash-replay path.

## 1. Lock-mode proxies read as the wrong mode

### 1.1 CAW `mxfs_v5_dlm_inode_held_rawmode()` reports a PR hold as EX

Source: `trap-caw-held-rawmode-reports-pr-hold-as-ex`.

- `mxfs_v5_dlm_inode_held_rawmode()` (dlm/v5_mount.c) returns `mxfs_dlm_caw_held() ? MXFS_LOCK_EX : MXFS_LOCK_NL` on CAW: any bit of this node in the slot, holders_pr included, reads as EX. On TCP it returns the real mirror mode. So `held_mode >= MXFS_LOCK_EX` is NOT an EX test on CAW.
- `mxfs_v5_dlm_inode_granted_mode()` returns the real per-node mode on both transports (CAW via `mxfs_dlm_caw_granted_mode` / `node_held_mode`).
- Cost: `mxfs_dlm_relog_authorized` (xfs/xfs_mxfs_relbar.c) gated the release drain's synthetic re-log (P146V) on held_rawmode, so a node releasing a PR hold of a shortform directory re-logged its stale in-core image over the EX holder's newer platter image.
- Measured on 4- and 8-node disk/caw/mpath boards (0.90.131): a removed LOCK/<node> entry came back, its inode number was freed and reused, chk_mxfs found nlink 1 named by two entries (D-CAW-MPATH-8NODE-REUSED-INODE-NAMED-BY-TWO-DIRENTS-NLINK-1-AFTER-SUITE).
- Signature: P-RELFLUSH-NOTENURE held_mode=3, P146V-UNLANDED, P58-DIRPIN-NONEX dlm_mode=0, P56-DIRWRITE mode=0 write=[...].
- Apply: any new check meaning "this node may write as owner" must read the granted mode (`mxfs_v5_dlm_inode_granted_mode`). Grep for `held_rawmode(` callers comparing against EX before trusting them on CAW.
- Directed repro: tests/relog_pr_release_auth.sh (dbg_relog_force_ino on a PR release, fresh prep, foreign=0 laps only).

### 1.2 `i_dlm_mode` is the target mode during reload

`compiled-mxfs-proxy-evidence-traps`, `trap-i-dlm-mode-is-the-target-mode-during-the-acquire-reload-so-held-ex-does-not-mean-this-node-wrote-the-fork`.

- `mxfs_reload_dir_format_revert_guard` (and its post-spin twin, `xfs/xfs_mxfs_reload.c`) kept the in-core block-form dir when `dirty || i_dlm_mode == EX`. The acquire path sets `i_dlm_mode` to the mode being acquired BEFORE reload runs, so a freshly granted EX looks like authorship. A clean stale fork (cc 195333) refused the newer shortform platter image (195339) and republished the stale copy: removed names returned naming freed inodes, renames lost (cold audit CORRUPT, 3 of 3 laps).
- Authority for the in-core fork is dirtiness (pin / `ili_fields` / in AIL) or a change count at or ahead of the platter, never `i_dlm_mode == EX` alone. A clean fork with `di_changecount > inode_peek_iversion()` is older than the platter.
- Log signature: `P190-MODIFY-BASE-BEHIND incore_chg < disk_chg`, then `P43-DIR-FMTREVERT-SKIP dirty=0`, then `P-CCREGRESS cc_disk > cc_writing`. `P-CCREGRESS` is a corruption-in-progress marker; grep it first on dangling/duplicated names.
- Prove a fix fired with a module-parameter counter (`dir_fmtrevert_behind_total`, sampled by `tests/fix_counter_watch.sh`); a dmesg ring holds seconds under load and read 0 for a line that fired 12 times.
- A directory at the shortform/block edge (9 names, the path-load shared dir) converts on every add/remove and is the workload that exposes format-revert bugs.

## 2. Change count, build identity and task-label proxies

### 2.1 Unwritten conversion and the change-count gate

`compiled-mxfs-proxy-evidence-traps`, `trap-xfs-unwritten-conversion-always-logs-the-core-so-it-moves-the-mxfs-change-count`.

- Hypothesis (false): an in-size unwritten->written conversion logs only the data fork, so `di_changecount` does not move, MXFS's forced bump (only when `XFS_ILOG_CORE` is logged, `xfs/libxfs/xfs_trans_inode.c`) is skipped, and the foreign replay's changecount gate / P-RELOAD-IDENTICAL drops the conversion (fsynced data reads as zeros).
- Fact: `xfs_bmapi_convert_unwritten` in `xfs/libxfs/xfs_bmap.c` ORs `XFS_ILOG_CORE` into logflags unconditionally (not for the COW fork). Every conversion takes the bump. Verified live on the physical pair, 31 growths with O_DIRECT + fdatasync, all 32 blocks intact on the peer.
- What does NOT bump the count: timestamp-only logs (`xfs_vn_update_time`) and the release drain's deliberately suppressed re-log. The replay's `P77-STALE-BASE-VERDICT buf_cc > platter_cc, log_cc == buf_cc, SKIP/SKIP` lines are later images of a count the replay already APPLYed in the same pass, not dropped writes.
- Test design: a sequential-conversion test must leave an unwritten tail past the last block written. Writing to the end of the fallocated range merges extents on the last conversion (count changes, core logged) and masks the question either way.
- Before claiming a changecount-gate hole for a transaction type, read the XFS committing caller for an unconditional `XFS_ILOG_CORE` (bmapi convert, size updates, nblocks changes all log core), then confirm with the P77-FRINODE probe (`echo 'format P77-FRINODE +p' > /proc/dynamic_debug/control`), not reasoning.

### 2.2 srcversion is not a content hash of the tree

`compiled-mxfs-proxy-evidence-traps`, `trap-srcversion-does-not-move-for-a-header-change-outside-the-objects-own-directory`.

- Changing `MXFS_PROTO_GEN` 21->22 in `include/mxfs/mxfs_super.h` rebuilt 8 objects and relinked, yet `srcversion` stayed byte-identical. modpost/sumversion folds in only dependencies in the same directory as the object, so the whole `include/` hierarchy, the on-disk format header included, is outside build identity. `modinfo` has no `version:` field and the image has no version string, so srcversion is the only identity the rig has.
- Consequence: "node srcversion == tree srcversion, therefore node runs this build" is unsound for any change confined to `include/`; a node on the old module is indistinguishable and the measurement is attributed to the wrong build.
- Force the deploy (`MXFS_FORCE_PREP=1`) when `include/` changed. Prefer a discriminator the running kernel prints, e.g. the C7 gate line `filesystem cluster_proto_gen=N but this kernel speaks M`. A new identity check answers "same same-directory sources", not "same build".

### 2.3 A validation that finds blockers is reported before anything moves

`compiled-mxfs-proxy-evidence-traps`, `feedback-a-validation-that-finds-blockers-is-reported-before-the-version-or-scope-moves`.

- Asked only to validate a named release (0.90.40, the DRBD release), the session found release-blocking defects, bumped VERSION to 0.90.41 and started fixing, unannounced. The user objected sharply: .40 was the DRBD release and the task was validation only.
- When validation surfaces something that changes what ships (new version number, code changes, different release name), state it in that turn with the evidence BEFORE moving the version or widening scope. The mechanical version-bump rule does not override the user's release naming; a renumber also means amending the README headline and CHANGELOG headline, and that call is theirs.

## 3. Sole survivor, takeover and crash replay: where "we are alone" or "it is done" is wrong

`compiled-sole-survivor-and-post-crash-actor-traps` (3.1 to 3.5). Central topic: the state of an MXFS node after a peer (or its own previous incarnation) died, and the repeated mistake of treating "no live peer" or "already handled" as meaning "nothing to coordinate". Covers guards, markers, caches, probes and audits that read clean on that path.

### 3.1 Dynamic-membership guards are wrong for the survivor

- `mxfs_v5_dlm_is_single_node()` is dynamic membership. The survivor of a 2-node cluster is single-node the instant its peer is fenced, but its inode cache still holds shells from while the peer lived. `xfs_lookup`'s dirent-type check was gated on `!is_single_node`; on `path_fence_degraded` the survivor opened 18 of 1256 of the dead node's fsynced files as directories (EISDIR) 1.4 s after recovery. Direct-attach boards and 3+ node runs never show it; only a row that reads the dead node's files from the lone survivor immediately does. A guard that skips peer-state validation must ask "has this mount ever had a peer" (`!is_single_node || mxfs_v5_dlm_sole_survivor`). Check that gate first when a 2-node death row fails on the survivor with a transient wrong answer. `trap-a-sole-survivor-skips-every-check-gated-on-is-single-node`
- D-0904 was closed FIXED AND VERIFIED after one call site (`mxfs_dlm_ilock_begin`) got `sole_survivor()`. The bug was the predicate: census was 390 `is_single_node` occurrences (~369 real calls) against 8 `sole_survivor` (5 real). Unaudited sites included `xfs_difree_finobt` (identical chunk-delete guard to the inobt one) and `mxfs_dialloc_two_phase` (candidate validator skipped entirely when single-node). When the root is a predicate, helper or idiom, closure needs a census of every use, or a class-level record stays open. Cheap check: `grep -rc` the unsafe and safe predicates and compare; 369:5 is the finding. `trap-closing-a-defect-on-one-call-site-leaves-the-class-open-368-to-5`
- Never-multi is the same shape in the other direction. The exemption "no successor writer can exist for what a never-multi mount logs" ignored the replayer. A lone TCP mount (mkdir + 40 creates + fsync, destroyed within a second) was replayed as a foreign slice; the directory-block image carried authority NONE / AUTH_NOT_HELD, the transaction was atomically skipped, AG 0 quarantined, every root lookup EIO. Corrected invariant: being alone permits omitting coordination with live peers, never the durable authority a future incarnation or foreign replayer needs; before the first dirty capture of an inode-owned replay-protected image the inode must hold durable authority named in the token (later promotion cannot repair a token captured NONE). When an argument says "no X can exist", enumerate the post-crash actors: replayer, returning incarnation, survivor taking over ledger pages. Every formation's first node runs alone, so a lone mount is not a corner case. Cheapest proof is the same workload without a crash through the producer's own probe on two membership arms. Harness traps: never reformat the LUN under a still-mounted peer; `xfs_bmap`/`xfs_io` cannot read an MXFS extent map (use `filefrag`); verdict greps for `refus` / `mismatch` match protocol stage lines, so assert the specific refusal probes instead. `trap-a-membership-exemption-justified-for-live-coherency-is-not-justified-for-crash-replay`

### 3.2 Gates, tenures and markers must be scoped to the actor that created them

- The kind-20 sole-survivor gate is a per-LUN WE(1) reservation held by one key. When the holder dies, a joiner can REGISTER but cannot WRITE, so the PR-ledger publish fails (`rc=-52`, mount aborted); a taken-over, already-certified descriptor never revisits the gate path, so the exclusion recheck lapses (`P239-GATE-LAPSED`) until the mount barrier expires. Rules: a certificate whose exclusion is a reservation by a specific key becomes unprovable when that key dies, so the successor re-proves under its own key; refuse-at-publish paths must first decide, read-only, whether the holder is dead and PREEMPT AND ABORT with the all-registrants type (WE-AR, not type 1); TCP has no whole-cluster bootstrap term, so total outage recovers slot by slot via the ordinary mount path. A "hazards ledgered" list in a design doc is a defect nobody's tool sees; file it in the queue. Fix `v5_gate_reprove`, `v5_tcp_dead_gate_holder`. `trap-the-sole-survivor-write-exclusive-gate-outlives-the-node-that-holds-it`
- A ledger record of this node's own incarnation imported on page takeover has `grant_gen 0`; the "already granted" shortcut in `dlm_lock` adopted it as-is, and the generation-aware release (`p_rel_gen == 0`) logged `P6Z-REL-NOTHING` forever while the peer's listing sat in D state 300 s+. Adopting an imported record is starting a tenure and must mint the generation (`P-TAUTH-ADOPT-LOCAL`); a record under our node id from a different incarnation is never adopted; a release arm finding "nothing held" must check the mirror for a generation-less own entry (`mxfs_dlm_unlock_genless`). Measurement: count the probe, not the verdict (a lap that imported nothing is clean but vacuous); a cold-check asserting zero P-SOLE-SURVIVOR is wrong because the sole arm fires one in phase 1 by design. `trap-an-authority-record-imported-for-our-own-incarnation-is-a-tenure-without-a-generation-and-the-gen-aware-release-skips-it`
- A per-attempt "may have run" marker must be scoped to the term that armed it. `fence_takeover` bumped the term but kept the dead term's `MXFS_RECOV_F_FENCE_CMD_MAY_HAVE_RUN`; the successor's first prove returned NO_RESERVATION (its own WE(1) gate was in force), and `mxfs_disklock_recovery_fence_retryable` refused the armed descriptor for good (mount rc 32, victim's slice never replayed). Ruling: fold the dead term's value into a separate `PRIOR_TERM_MAY_HAVE_RUN` history bit (forbids reading key absence as the dead command's success, nothing else), clear the current bit with the new term, key retry on the current bit only. Rejected: retry keyed on volatile memory, deferring takeover while another gate is in force. Fix 0.89.9 `dlm/disklock.c`. `trap-a-taken-over-fencing-attempt-inherits-the-dead-terms-armed-marker-and-the-retry-worker-refuses-it-for-good`
- A per-slot "already retired for pub_seq N" marker aliased the slot's next victim: pub_seq restarts at 1 per recovery case and a heartbeat slot is reused, so the second death into the same slot on the same surviving mount skipped retirement and left the dead node's AG 1 EX in the TCP master table (61 s acquire timeouts, `P-LKTIMEOUT-HOLDER` to 452 s). Key any "already done for this case" state on victim incarnation (epoch) plus the case counter, and clear it on publish. A single lap on a fresh mount cannot show it; consecutive laps without re-prep are the cheapest reproducer for slot aliasing. `trap-a-per-slot-marker-keyed-on-a-per-case-sequence-aliases-the-slots-next-victim`
- A revisit gate keyed on the durable ambiguity marker (MAY_HAVE_RUN) was blind to "proved but unpublished" (exclusion proved, certificate CAS failed; sole-survivor-gate proofs never arm the marker). Result: `P238-FENCE-HOLDER-STATE state=LIVE` every ~30 s forever, peer mount rc 32, takeover cannot help because the holder is us. State a gate in terms of the condition it exists for ("this node holds an unfinished attempt nothing else can take over") and enumerate the ways to reach it. The 0.89.13 gate accepts the durable arm or local `MXFS_RBLK_CERT_UNRECORDED`; the arm that caught it asserted the consequence (peer mounts), not just the mechanism, and every mechanism assertion had passed. `trap-a-revisit-gate-keyed-on-the-ambiguity-marker-cannot-see-a-proof-that-was-never-published`

### 3.3 Recovery is a cache producer outside the grant discipline; fixes scoped to one inode type skip the rest

- Survivor replay of a dead peer's slice reads every logged block through its own cache and leaves it clean `XBF_DONE` with no tenure (158 bmbt + 2 AG-btree images after a 20000-extent kill), so tenure-end eviction never runs. A `rm F; rebuild F2` reproduction reuses the same inode number, acquire-time eviction (keyed `bb_owner == ino`) clears all 158, and the lap proves nothing; free the inode number with an empty file first so the consumer's identity differs from the old owner's. A raw tagged-cache-hit counter is nonzero during recovery; split hits by task. Fix hazards: tag by producer at the recovery task's read (disable recovery readahead on foreign replay), never clear provenance from an I/O completion, fence after home flush and before IMAGES_REPLAYED/purge, busy images are a retryable error, one log force only, explicit exemptions for fixed-address classes with unknown ops failing closed, verify against an external content oracle (writers' block lists) rather than two nodes agreeing, add a partial-retirement retry arm. Rig: never `make` or edit a running harness during a death/rejoin lap. `trap-a-dead-peers-slice-replay-populates-the-survivors-cache-under-no-tenure-and-same-inode-reuse-hides-it`
- D-0973: reload bmbt eviction, iread FUA refresh and the bmbt tenure write gate were all `S_ISDIR`-gated while `mxfs_iflush_force_bmbt_durable` was file-inclusive. A regular file whose data fork went BTREE kept a stale 15-record leaf (3620 of 3635 writes EFSCORRUPTED, 1818 torn flushes). When a coherency mechanism is gated on inode type, ask what the other types do on the same path; read/write asymmetry is the bug. Exercise with a regular-file workload that reaches BTREE (EXTEND=1 sparse, EXTSPAN for multi-leaf/two-level). Detector trap: "if_broot numrecs == 1" means one leaf only when `bb_level == 1`; a level-2 root with one pointer gave 42 false tears and 5791 unratelimited lines per 90 s. `trap-directory-scoped-coherency-fixes-silently-skip-regular-files-with-btree-extent-maps`

### 3.4 Instruments and audits that read clean or alarmed wrongly

- A changecount is monotonic within an incarnation, not across reallocation. `mxfs_dino_clobber_probe` flagged 7 "platter clobbers" that were the survivor's new inodes (cc restarts at 1, random generation) over the peer's freed numbers; the predicate needs incarnation (same generation and behind, or platter holds the freed successor at generation+1). Likewise the "6 unauthorised passenger slots" in the root cluster include the realtime bitmap/summary inodes (ino 129/130, created by mkfs, never in core); read per-slot `P218-CLUSTER-PASSENGER` lines, not the sum. "Unauthorised" and "stale" are different instruments; only a platter compare answers stale. `trap-a-changecount-regression-probe-must-be-incarnation-aware-and-the-root-cluster-passengers-are-the-rt-inodes`
- A cold audit that checks only what entries name passes a lost name, because the inode it named is still valid and its nlink still counts the lost name. A link lap losing 86 names read `dangling=0`; `chk_mxfs` `check_dirents` now counts every entry (including `.` and `..`) against di_nlink and reports `nlink_mismatch=` and `disconnected=` (calibrated 31,530 inodes, 0 mismatches). Any CLEAN audit predating 0.90.37 does not cover lost-name damage; re-audit kept images. Attribution trap: in the rmdir/mkdir race, parents are freed and numbers reused within seconds, so `..` pointing at a reused incarnation is not a live-parent lost update; compare crtimes or rerun the fixed build. When a corruption class leaves the damaged object looking valid, check a cross-object invariant (count or reachability). `trap-a-cold-audit-without-link-counts-passes-a-lost-name-because-the-inode-it-named-is-still-valid`

### 3.5 Common thread

Each failure came from keying a decision on current/visible state (live membership, the familiar marker, the per-case counter, the object itself, the directory case) when the correct key was history or identity (ever had a peer, current term, victim epoch, cross-object count, every inode type). Verification that exercises one lap, one call site, or one mechanism passes; verification of the consequence across consecutive laps, a census, or a no-crash control arm does not.
